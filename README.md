# 🐑 🐰 🧜‍♀️ 🐯 한국특허정보원 카드배틀

맵 네 모서리의 **장소**에서 카드를 뽑아 중앙 **동물 스택**에 쌓고, 같은 동물이 **짝수 장**이 되는 순간 통째로 가져오는 할리갈리/고스톱류 실시간 N:N 팀 대전 웹 게임입니다. 4대 지식재산권(실용신안·상표·디자인·특허)을 의인화한 아기 동물 카드 4종이 등장합니다.

| 카드 | 지식재산권 | 한 줄 |
|---|---|---|
| 🐑 **실용신양** | 실용신안 | "빠르게 등록해 실리를 챙기는 내 권리!" |
| 🐰 **상표토끼** | 상표 | "점점 더 브랜드 가치가 더해진다!" |
| 🧜‍♀️ **디자인어** | 디자인 | "보기 좋은 떡이 먹기도 좋다!" |
| 🐯 **특허랑이** | 특허 | "독점적 실시를 통해 상대를 억제한다!" |

> 배포판: <https://ip-card-battle-render.onrender.com>

## 게임 방법

### 1. 장소를 클릭해 카드를 뽑는다

맵 네 모서리의 장소마다 **나올 수 있는 동물**과 **카드 숫자 범위**가 다릅니다. 장소를 클릭하면 슬롯머신처럼 동물과 숫자가 돌다가 확정되어 중앙의 해당 동물 스택으로 날아갑니다. 카드 재고나 보충 개념은 없어서 뽑기는 언제나 무한입니다.

| 장소 | 나오는 동물 | 카드 숫자 |
|---|---|---|
| 🏠 오두막 | 🐰 토끼 / 🐑 양 | `5~10` |
| 🌲 숲길 | 🐰 토끼 / 🐑 양 / 🐯 호랑이 | `10~15` |
| ⚓ 부둣가 | 🧜‍♀️ 인어 / 🐯 호랑이 | `5~10` |
| 🏞️ 강가 | 🧜‍♀️ 인어 / 🐰 토끼 / 🐑 양 | `10~15` |

동물이 3종인 장소는 숫자가 크게(`10~15`), 2종인 장소는 작게(`5~10`) 나옵니다. **원하는 동물이 나올 확률**과 **큰 숫자**를 저울질하는 것이 뽑기의 핵심입니다.

**시작 공유 카드** — 게임은 빈 보드가 아니라 **서로 다른 동물 카드 2장**(숫자 `7~13`)이 중앙에 깔린 채로 시작합니다. 어느 팀 것도 아닌 공유 카드이며, 빈 보드에서는 선 플레이어가 무엇을 뽑아도 짝을 만들 수 없어(그 짝을 바로 다음 차례인 상대가 가져갑니다) 생기던 선 플레이어의 불합리를 없애기 위한 장치입니다. 두 장은 항상 다른 동물이라 시작하자마자 정산되는 일은 없습니다.

### 2. 짝수 장이 모이면 그 자리에서 획득

중앙 스택에 같은 동물의 **미획득 카드가 짝수 장**이 되면, 그 순간 그 동물의 카드를 전부 가져오고 **숫자 합만큼 경험치**를 얻습니다. 정산은 이번 차례에 뽑을 카드를 모두 뽑은 뒤(예약된 추가 뽑기 포함) 한 번에 이루어집니다.

경험치는 **동물별로 따로** 쌓이고, 레벨은 `floor(경험치 ÷ 임계값)`입니다.

### 3. 턴을 마칠 때 행동 하나를 고른다

정산이 끝나면 **레벨이 1 이상인 동물** 중 하나를 골라 행동을 씁니다(쓸 수 있는 게 없으면 자동으로 넘어갑니다). 고른 동물의 경험치는 `레벨 × 임계값`만큼만 차감되고, 임계값을 넘겨 쌓아둔 초과분은 다음 레벨을 위해 남습니다.

| 동물 | 임계값 | 효과 |
|---|---|---|
| 🐑 실용신양 | 10 | 다음 내 턴에 무작위 장소에서 `레벨 × 배율`회 **추가로 뽑기** |
| 🐰 상표토끼 | 10 | 내 체력 **+`레벨 × 배율`** |
| 🧜‍♀️ 디자인어 | 20 | **대기 배율에 레벨을 더함**(자기 자신은 배율을 소모하지 않음) |
| 🐯 특허랑이 | 20 | 상대 체력에서 `레벨 × 배율`만큼 **강탈**(상대 −n, 나 +n) |

**배율(디자인어)** — 인어를 고르면 "다음 행동이 그 레벨만큼 **더 발동**"합니다. 대기 배율은 기본값 1(=기본 1회)에서 시작해 인어를 쓸 때마다 그 레벨만큼 **더해져 누적**됩니다(곱연산이 아니라 합연산 — 레벨 2를 두 번 쌓으면 1+2+2=5). 인어 외의 행동을 쓰면 그 효과가 누적된 배율만큼 발동하고, 사용 직후 배율은 1로 돌아갑니다. 인어를 몇 번 쌓았다가 호랑이로 터뜨리는 것이 이 게임에서 가장 큰 한 방입니다.

몇 가지 짚어둘 점:

- **경험치와 체력(점수)은 완전히 분리된 자원입니다.** 행동으로 얻은 체력은 절대 경험치로 돌아오지 않고, 경험치는 체력을 직접 올리지 않습니다.
- 🐯 특허랑이의 강탈은 **보존형**입니다 — 상대가 가진 만큼만 뺏으며 오버킬이 없습니다.
- 🐑 실용신양의 추가 뽑기 예약은 **누적이 아니라 덮어쓰기**이고, 안전 상한(40회)이 있습니다.

### 4. 도토리 축제

`festivalTurn`(기본 **8턴**)에 도달하면 축제가 시작됩니다. **한 번 터지고 끝나는 이벤트가 아니라**, 그 턴부터 **매 턴 계속** 다음 차례 팀에게 실용신양과 똑같은 방식의 "도토리 뽑기"가 예약됩니다(A/B 구분 없이 자기 차례가 오면 무조건). 축제가 시작되는 순간, 이 방에 실제 적용되는 규칙("이제부터 K턴마다 추가 랜덤 뽑기 N회!")을 화면 중앙에 큼직하게 안내합니다.

`festivalDrawIncreaseInterval`(k)턴이 지날 때마다 매 턴 예약되는 횟수가 `n×1 → n×2 → n×3 …`으로 한 단계씩 올라갑니다. 기본값 k=2라 2턴마다 한 단계씩 계속 올라갑니다(끝없이 커지는 걸 원치 않으면 k를 999에 가깝게 크게 잡아 사실상 증가를 막을 수 있습니다).

### 5. 승패

체력은 `targetScore`(기본 10)에서 시작합니다.

- **즉시 승리** — 내 체력이 `targetScore × 2`(기본 20) 이상
- **즉시 패배** — 내 체력이 0 이하
- **턴 종료** — 20턴을 넘기면 체력이 높은 팀 승리(같으면 무승부)

## 방장이 정하는 규칙

방을 만들 때(싱글 모드 포함) "⚙️ 게임 규칙"을 펼쳐 조정할 수 있고, 방을 만든 뒤에도 **대기실에서 방장이 계속 고칠 수 있습니다**("⚙️ 게임 규칙 바꾸기" → 값 수정 → "규칙 적용"). 게임이 시작되면 그때 값으로 굳어 바뀌지 않습니다.

| 항목 | 기본값 | 범위 | 설명 |
|---|---|---|---|
| 선 플레이어 | 팀 1 | 팀 1 / 팀 2 / 무작위 | 먼저 시작하는 팀 |
| 목표 점수 | 7 | `1~100` | 시작 체력이자 승리 격차(승리 체력 = ×2) |
| 도토리 축제 시작 턴 | 6 | `1~999` | 이 턴부터 매 턴 도토리 뽑기 예약(최대 턴수를 넘는 값은 마지막 턴으로 암묵 처리) |
| 도토리 뽑기 횟수 | 1 | `1~20` | 축제 1단계에서 매 턴 예약되는 횟수(n) |
| 뽑기 증가 주기 | 2 | `1~999` | k턴마다 n×1 → n×2 → … (999에 가깝게 크게 잡으면 사실상 증가 없음) |
| 동물 뽑기 제한시간 | 30초 | `5~120` | 장소를 고르는 시간 |
| 행동 선택 제한시간 | 15초 | `5~60` | 턴 종료 행동을 고르는 시간 |
| 행동할 게 없을 때 | 3초 | `2~30` | 고를 수 있는 행동이 없을 때의 대기 |

제한시간을 넘기면 서버가 대신 처리합니다(장소 대기 중이면 무작위 장소, 행동 대기 중이면 무작위 유효 행동 또는 자동 패스). 실용신양으로 예약된 추가 뽑기가 있으면 1회당 10초씩(최대 6회분) 턴 시간이 늘어납니다.

## 플레이 환경

- **멀티플레이** — 방을 만들면 4글자 방 코드(헷갈리는 `O`·`I` 제외)가 나옵니다. 상대는 다른 브라우저나 시크릿 창으로 참가하세요(같은 브라우저의 새 창은 세션 정보를 공유해 충돌합니다). 팀 인원은 N:N이며 팀 안에서 순서대로 돌아가며 플레이합니다.
- **대기실 / 방장** — 방을 만든 사람이 방장(👑)입니다. 대기실에서 방장은 **초대 링크·방 코드 복사**, **팀 이름 바꾸기**, 참가자 **팀 강제 이동 / 내보내기 / 방장 넘기기**, **게임 규칙 수정**, **게임 시작**을 할 수 있습니다. 참가자는 자기 자리(팀 1 / 팀 2 / 관전석)만 스스로 바꿀 수 있고 "준비"를 눌렀다 취소할 수 있습니다. 방장이 대기실에서 나가면 남아 있는 사람 중 가장 먼저 들어온 사람이 방장을 이어받습니다.
- **닉네임 · 팀 이름은 비워둬도 됩니다** — 닉네임을 비워두면 입력창에 흐리게 떠 있던 `{형용사} {동물}`(예: "심술궂은 라쿤", 5,070가지) 이름 그대로 참가합니다. 팀 이름은 방을 만드는 순간 양 팀 모두 `{지식재산권} {조직}` 형태(예: "특허 수호대", 45가지)로 자동 배정됩니다. 입력창 옆 🎲를 누르면 마음에 들 때까지 다시 뽑을 수 있고, 이미 적어둔 글자가 있어도 새 이름으로 덮어씁니다. 두 팀 이름이 같으면 게임 중 우리 팀을 구분할 수 없으므로 저장·시작이 막힙니다.
- **관전 모드** — 방을 만들거나 참가할 때 팀 1·팀 2 외에 **👀 관전자**를 고를 수 있습니다(대기실에서 서로 오갈 수도 있습니다). 관전자는 카드를 뽑거나 행동을 고를 수 없고 양 팀의 대결을 지켜보기만 합니다 — 동물 현황판에 마우스를 올려 설명을 보거나, 우하단 ⚙️ 설정을 여는 것은 그대로 됩니다. 관전자는 인원수·준비 상태에 들어가지 않아서 관전자가 몇 명이든 게임 시작을 막지 않습니다. 관전 화면에서는 "우리 팀 연두 / 상대 팀 붉은색"이라는 기준이 없으므로 **양 팀이 각자의 색(기본: 팀 1 민트, 팀 2 핑크)** 으로 칠해지고, 지금 차례인 팀을 알려주는 **👇 손가락**이 그 팀 색 후광을 두르고 양 팀 차례 모두에 나타납니다(색은 `client/lib/teamColors.ts`에서 한 번에 바꿀 수 있습니다).
- **대기실 채팅** — 대기실에는 채팅창이 항상 열려 있습니다(게임 화면에는 없습니다). 사람이 친 말과 함께 방에서 일어난 일(입장·퇴장·추방·팀 변경·방장 위임·팀 이름/규칙 변경)이 회색 안내줄로 같이 흘러, 방금 무슨 일이 있었는지 알 수 있습니다. 나중에 들어오거나 재접속해도 최근 대화 50줄이 복구됩니다.
- **초대 링크** — 대기실의 "🔗 초대 링크 복사" 버튼이 `주소/?room=방코드` 형태의 링크를 복사합니다. 그 링크로 들어오면 참가 화면이 방 코드가 채워진 상태로 열립니다.
- **싱글 모드** — B팀을 CPU가 채웁니다. CPU는 자기 차례마다 잠깐 뒤 행동하며, 즉시 이길 수 있는 수가 있으면 그것을 고릅니다.
- **재접속** — 새로고침하거나 연결이 끊겨도 같은 브라우저라면 저장된 플레이어 ID로 자동 재접속해 진행 중인 판으로 돌아갑니다.
- **설정(우하단 ⚙️)** — 전체/효과음/BGM 음량과 음소거, **글씨 크기 7단계**(기본 4단계)를 조절합니다. 글씨 크기는 레이아웃은 그대로 두고 글자만 키우고 줄이며, 브라우저에 저장됩니다.
- **게임 방법** — 로비의 "📖 게임 방법" 버튼에서 한 장짜리 포스터형 안내를 볼 수 있습니다.

## 기술 스택 & 구조

npm workspaces 모노레포입니다.

- **`shared/`** — 타입(`types.ts`)·상수(`constants.ts`)·WebSocket 프로토콜(`protocol.ts`)·무작위 이름 생성(`names.ts`). 클라이언트·서버가 `shared` 패키지명으로 함께 씁니다.
- **`server/`** — Node.js + `ws`. TypeScript를 `ts-node`로 직접 실행합니다.
- **`client/`** — Next.js (App Router) + TypeScript + Tailwind CSS v4.

```
ip_card_battle_render/
├── server.ts             # 배포용 통합 서버 (Next.js + WS를 같은 포트에)
├── Dockerfile            # 단일 이미지 / 단일 포트
├── shared/               # 타입·상수·프로토콜·무작위 이름(names.ts)
├── server/
│   ├── index.ts          # 로컬 개발용 WS 서버(8080)
│   ├── gameServer.ts     # WS 연결 핸들러(메시지 타입별 분기)
│   ├── roomManager.ts    # 방 코드 발급·조회·정리
│   ├── room.ts           # 방 하나의 상태 머신(로비 → 게임 → 브로드캐스트)
│   └── engine/           # 순수 게임 로직 (UI와 완전 분리, 단위 테스트 대상)
│       ├── places.ts     # 장소별 동물·숫자 규칙
│       ├── drawCard.ts   # 예약 뽑기 소모 → 뽑기 → 짝수 정산
│       ├── skills.ts     # 행동 4종(레벨·배율 계산, 경험치 소모)
│       ├── turnManager.ts# 턴 교대, 축제 예약, 승패 판정
│       └── gameEngine.ts # processPlayerAction → processSkillChoice 2단계 진입점
└── client/
    ├── app/              # 로비(/) · 게임(/room/[roomId])
    ├── components/game/  # 보드·장소 타일·동물 스택·팀 패널
    ├── components/effects/ # 슬롯머신·양털·호랑이 발톱·도토리 등 연출 레이어
    ├── hooks/useAnimationQueue.ts # 서버 이벤트 → 연출 타임라인 스케줄러
    └── lib/preload.ts    # 시작 시 효과음·이미지 프리로드
```

**설계 원칙**

- **서버가 유일한 진실.** 카드는 뽑히는 즉시 공개되므로 숨길 정보가 없고, 모든 랜덤(동물·숫자, 추가 뽑기 장소, 시간초과 시 대신 고르는 선택)은 서버에서만 생성됩니다. 턴 타이머도 서버가 `turnDeadline` 타임스탬프로 관리하며 클라이언트 타이머는 표시 전용입니다.
- **연출은 서버 이벤트의 번역이다.** 서버는 매 액션마다 `GameEvent[]`와 최신 상태를 함께 보내고, 클라이언트는 이를 "슬롯 스핀 → 카드 노출 → 흔들기 → 팀으로 날아가기 → 경험치 반영 → 레벨업" 순서의 타임라인으로 재생합니다. 그래서 화면상 상태(카드 목록·표시 경험치·활성 팀)를 서버 진실과 별도로 관리합니다.

## 배포

Render처럼 서비스당 포트를 하나만 외부로 공개하는 플랫폼에서는 WS용 포트를 따로 열 수 없으므로(브라우저가 WS 서버에 직접 접속하는 구조라 그 포트가 공개되지 않으면 접속 자체가 안 됩니다), 루트 `server.ts`가 Next.js 커스텀 서버 위에 **같은 HTTP 서버·같은 포트**로 `/ws` 경로의 WebSocket을 함께 띄웁니다.

```bash
# 로컬에서 통합 서버로 실행
npm run start            # ts-node --transpile-only server.ts

# Docker
docker build --build-arg NEXT_PUBLIC_WS_URL=wss://<호스트>/ws -t ip-card-battle .
docker run -p 3000:3000 ip-card-battle
```

`NEXT_PUBLIC_*`는 **빌드 시점에 고정**되므로, 외부 도메인에 배포할 때는 반드시 빌드 인자로 `wss://<호스트>/ws`를 넘겨야 합니다.

## 에셋

`client/public/` 아래 파일 목록은 **빌드 시점에** `client/scripts/generateAssetManifest.mjs`가 훑어 `client/lib/assetManifest.ts`로 굳힙니다(`predev`/`prebuild`에서 자동 실행). 게임 시작 전 로딩 화면에서 효과음과 이미지를 전부 미리 받아두므로, 첫 효과음이 늦거나 카드 이미지가 뒤늦게 뜨는 일이 없습니다.

> 런타임에 `public/`을 읽는 API 라우트를 쓰면 안 됩니다 — 배포 구성에서는 프로세스의 작업 디렉토리가 프로젝트 루트라 `public/` 경로가 어긋나 목록이 비어버립니다(효과음이 전혀 나지 않던 실제 원인).

**효과음** — `client/public/sounds/`에 접두사 규칙으로 넣으면 자동으로 잡힙니다(파일이 없어도 무음으로 정상 동작).

| 접두사 | 재생 시점 |
|---|---|
| `card_*.mp3` | 장소에서 카드를 뽑을 때마다(연속 뽑기는 음이 조금씩 올라감) |
| `sheep_*.mp3` | 실용신양 행동 발동 시 |
| `rabbit_*.mp3` | 상표토끼 행동 발동 시 |
| `mermaid_*.mp3` | 디자인어 행동 발동 시 |
| `tiger_*.mp3` | 특허랑이 행동 발동 시 |
| `bomb.wav` / `bomb_*` | 도토리 축제 시작 순간(3연타) |

**BGM** — 로비 `bgm_main.mp3` → 게임 진행 `bgm_game1.mp3` → 축제 시작 후 `bgm_game2.mp3` → 종료 화면 `bgm_opening.mp3`. 용량이 커서 프리로드 대상에서는 제외하고 스트리밍합니다.

**이미지** — `places/`(장소 배경·텍스트), `emoticon/`(동물 표정 5종 × 4마리), `skills/`(행동 일러스트), `howto/`(게임 방법 포스터).
